Settings & Configuration

OpenBB Python reads its configuration from ~/.openbb_platform/, a folder in the current user's home directory. user_settings.json holds provider credentials, preferences, and per-command defaults. system_settings.json holds logging, extension permissions, REST API metadata, and HTTP settings. A .env file in the same folder sets environment variables. Importing openbb creates the folder and both JSON files when they do not exist.

The settings in effect for a session are exposed as obb.user and obb.system.

from openbb import obb

obb.user.preferences
obb.system.api_settings

Resolution order​

Python interface​

When from openbb import obb runs, values in system_settings.json and user_settings.json replace the built-in defaults. Environment variables, including those declared in ~/.openbb_platform/.env, supply credentials and the OPENBB_* flags listed under Environment variables. A variable in .env never replaces one already set in the shell.

A non-empty credential in user_settings.json takes precedence over the matching environment variable. The environment variable is used when the key is missing from the file or its value is an empty string. allow_on_command_output and allow_mutable_extensions work the other way around: the environment variable sets the default, and a key in system_settings.json overrides it.

The Python interface does not apply the [system] or [user] tables of openbb.toml. Extensions that define their own tables, such as [news] for openbb-news, read them from the file locations listed in the next section.

Changes made through obb.user last for the current session and are not written back to user_settings.json. obb.system is read-only; edit system_settings.json and restart the interpreter to change it.

obb.user.credentials.fred_api_key = "your-fred-key"
obb.user.preferences.output_type = "dataframe"

openbb-api and openbb-mcp​

The openbb-api and openbb-mcp launchers read openbb.toml at startup. They first load ~/.openbb_platform/.env and the file named by OPENBB_ENV_FILE into the environment, again without replacing variables that are already set. They then merge TOML from the locations below; a higher row takes precedence over a lower one.

PrecedenceLocation
4 (highest)The file passed with --config-file, or named by an environment variable: OPENBB_API_CONFIG or OPENBB_CONFIG for openbb-api; OPENBB_MCP_CONFIG, OPENBB_API_CONFIG, or OPENBB_CONFIG for openbb-mcp.
3The nearest openbb.toml or .openbb.toml, searching from the working directory upward.
2~/.openbb_platform/openbb.toml or ~/.openbb_platform/.openbb.toml.
1 (lowest)The [tool.openbb] table of the nearest pyproject.toml above the working directory.

Tables merge key by key across layers, while strings, numbers, booleans, and lists replace the earlier value. A layer that fails to parse is skipped, except the explicit file, which stops the launcher with an error.

The merged [system] table and the top-level keys described under openbb.toml are applied on top of system_settings.json. Commands executed through either launcher read credentials, preferences, and command defaults from user_settings.json and the environment on every request, so [user] tables in openbb.toml do not reach command execution. Keep those values in user_settings.json or in environment variables.

Tables that only the launchers consume, such as [env], [launcher] for openbb-api, and [mcp] for openbb-mcp, are documented on the respective extension pages.

user_settings.json​

{
  "credentials": {
    "fred_api_key": "your-fred-key",
    "bls_api_key": "your-bls-key"
  },
  "preferences": {
    "output_type": "dataframe",
    "show_warnings": true
  },
  "defaults": {
    "commands": {
      "/news/company": {
        "provider": ["tmx", "nasdaq"],
        "limit": 20
      },
      "/fred/economy/fred_series": {
        "frequency": "m",
        "transform": "pc1"
      }
    }
  }
}

The file must be valid JSON. A trailing comma or a comment makes import openbb fail with json.decoder.JSONDecodeError.

Credentials​

The credential fields are built from the installed provider extensions. Each provider's credential names are prefixed with the provider name.

Provider packageNamespaceCredential
openbb-blsobb.blsbls_api_key
openbb-cftcobb.cftccftc_app_token
openbb-government-usobb.uscongresscongress_gov_api_key
openbb-us-eiaobb.eiaeia_api_key
openbb-fredobb.fredfred_api_key

The other V5 providers define no credentials. Some endpoints of the providers above run without their credential; the ones that need it raise Missing credential '<name>' when it is not set.

Every credential can also be supplied as an environment variable with the same name in upper case, such as FRED_API_KEY. In addition, any environment variable whose name ends in API_KEY is added to obb.user.credentials under its lower-case name.

Credential values are stored as Pydantic SecretStr objects and print masked. obb.user.credentials.show() prints them unmasked, and obb.user.credentials.origins maps each installed provider to the credential names it uses.

Command defaults​

defaults.commands maps a command path to default parameter values. Paths can be written as URL paths (/news/company) or in dotted form (news.company).

provider accepts a string or a list of provider names. In the Python interface, a command called without provider uses a single configured provider as is. With a list, it uses the first provider whose credentials are all set; providers without credentials always qualify. If none qualifies, the command raises Provider fallback failed. Commands with no configured provider use their installed providers in alphabetical order under the same rule.

Any other key sets a parameter default. The default applies when the call leaves that parameter unset, and an explicit argument always wins. With the file above, the following call uses tmx and returns at most 20 articles.

obb.news.company(symbol="RY")

The REST API applies the same parameter defaults but ignores provider; requests select the provider with their own provider parameter. Defaults do not change function signatures or docstrings. The V4 key name routes is no longer read; rename it to commands.

  "api_settings": {

      "allow_origins": ["https://example.com"]
    }

      "proxy": "http://proxy.example.com:8080"

Logging​

With logging_suppress set to false, each command is logged with its route, arguments, provider, and any error. Files go to <data_directory>/logs/<installation-id>/, one per session, and rotate at the logging_frequency interval: day, hour, minute, or second. Log files older than five days are deleted when a new file handler starts. logging_handlers accepts file, stdout, stderr, and noop, and logging_verbosity is a standard logging level, where 20 is INFO. The logger is named openbb.logging_service.

import logging

logger = logging.getLogger("openbb.logging_service")

OBBject extension permissions​

An OBBject extension that sets on_command_output=True runs on command results before they are returned. If such an extension is installed and allow_on_command_output is false, importing openbb raises RuntimeError. An extension that also sets immutable=False can modify the result in place and additionally requires allow_mutable_extensions. These extensions block until they finish, and their changes are not reflected in function signatures or docstrings. Install them only from trusted sources.

openbb.toml​

openbb-api and openbb-mcp read the [system] table and a set of top-level keys from the cascade described under Resolution order.

debug-mode = true
logging-suppress = false

[system.api_settings.cors]
allow_origins = ["https://example.com"]

[system.python_settings.http]
proxy = "http://proxy.example.com:8080"

[system.python_settings.uvicorn]
host = "127.0.0.1"
port = 8080

The top-level keys are debug_mode, test_mode, headless, logging_suppress, allow_mutable_extensions, and allow_on_command_output. Each can be written in snake case or kebab case (debug-mode) and is equivalent to the same key under [system]; when both are present, the top-level key wins. The launchers also export each one as OPENBB_<KEY>, for example OPENBB_DEBUG_MODE, unless that variable is already set, so debug-mode = true turns on full tracebacks.

Keys inside [system] and its sub-tables must match the field names in the tables above exactly. Setting prefix under [system.api_settings] has no effect; set version instead.

Environment variables​

Boolean variables accept true, t, 1, yes, y and false, f, 0, no, n, in any letter case. Other values raise ValueError. Variables are read when openbb is imported or a launcher starts, so set them beforehand.

VariableDefaultEffect
OPENBB_DEBUG_MODEfalseRaise exceptions with their full traceback instead of the condensed [Error] -> message. The REST API re-raises instead of returning an error response.
OPENBB_AUTO_BUILDtrueOn import, rebuild the openbb package when the installed extensions differ from the last build. With false, run openbb-build after installing or removing extensions.
OPENBB_DEV_MODEfalseAdd the /system and /user/me endpoints, under the API prefix, to the REST API. /user/me returns stored credentials in plain text.
OPENBB_API_AUTHfalseRequire HTTP Basic authentication on REST API endpoints.
OPENBB_API_USERNAMEunsetUsername accepted when OPENBB_API_AUTH is on. Requests are rejected unless both username and password are set.
OPENBB_API_PASSWORDunsetPassword accepted when OPENBB_API_AUTH is on.
OPENBB_API_AUTH_EXTENSIONunsetName of an installed openbb_core_extension entry point whose module provides router, auth_hook, and user_settings_hook, replacing the built-in Basic authentication.
OPENBB_ALLOW_ON_COMMAND_OUTPUTfalseDefault for allow_on_command_output.
OPENBB_ALLOW_MUTABLE_EXTENSIONSfalseDefault for allow_mutable_extensions.
OPENBB_CONFIGunsetPath of the highest-precedence openbb.toml layer.
OPENBB_ENV_FILEunsetAdditional .env file loaded by openbb-api and openbb-mcp.
HTTP_PROXY, HTTPS_PROXYunsetProxy used by the core HTTP helpers.
REQUESTS_CA_BUNDLEunsetCA bundle used by the core HTTP helpers.
Credential name in upper case, such as FRED_API_KEYunsetProvider credential. See Credentials.

To persist variables, add them to ~/.openbb_platform/.env:

FRED_API_KEY=your-fred-key
OPENBB_DEBUG_MODE=true

To set one for the current session only, assign it before importing openbb:

import os

os.environ["OPENBB_DEBUG_MODE"] = "true"

from openbb import obb
